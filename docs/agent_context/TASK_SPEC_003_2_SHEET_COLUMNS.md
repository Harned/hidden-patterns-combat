# TASK_SPEC_003_2_SHEET_COLUMNS

## Текущая задача

Дать пользователю в UI доступ к **полному списку flatten-колонок**
выбранного листа для редактирования column mapping, а не только к
колонкам, уже распределённым по ролям preflight'ом.

## Контекст

После `TASK_SPEC_003` пользователь может:

* запустить preflight,
* увидеть автоматически распределённые колонки,
* изменить/удалить роль у уже назначенных колонок.

Чего **нельзя** сделать сейчас:

* добавить роль колонке, которую preflight не распознал;
* увидеть все колонки листа с примерами значений, чтобы принять
  решение о роли осмысленно.

## Что должно появиться

1. **algo** — утилитная функция `list_flatten_columns(path, sheet,
   header_rows)` возвращает список вида `[{name, levels, sample_values,
   dtype, role_hint}]`, где `role_hint` — результат работы
   эвристики `_assign_role` на уровнях колонки (подсказка, которую UI
   может показывать рядом с селектором).
2. **backend** — новый эндпоинт
   `GET /api/sources/{id}/sheets/{sheet_name}/columns?header_rows=0,1,2`
   возвращает этот список; проверка владения источником.
3. **frontend** — `MappingEditor` при смене активного листа (или
   после preflight) запрашивает полный список колонок и отображает все
   их в таблице, сохраняя текущие роли и показывая `role_hint` и
   sample values.

## Что НЕ делает этот шаг

* Не меняет формат `ColumnMappingConfig`.
* Не меняет алгоритм preflight.
* Не добавляет HMM.

## Definition of Done

1. На реальном `docs/Оценка СД содержание.xlsx` редактор mapping
   для выбранного листа показывает все ~70 колонок c примерами
   значений.
2. Пользователь может назначить роль колонке, которую preflight
   оставил без роли.
3. Сохранение mapping работает по существующему `PUT /api/sources/{id}/mapping`.
4. Инварианты сохранены: observations = ЗАП, HMM-полей нет.
5. Тесты зелёные, ruff/tsc clean.
