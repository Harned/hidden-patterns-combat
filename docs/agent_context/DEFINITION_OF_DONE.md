# DEFINITION_OF_DONE

## Общие критерии

Результат считается готовым только если:

1. Он соответствует предметной постановке.
2. Он проверяем.
3. Он воспроизводим.
4. Он не имитирует научный вывод без оснований.
5. Он не ломает существующую работоспособность.
6. Есть понятные команды запуска.
7. Есть описание ограничений.

## Для архитектурной итерации

Готово, если агент:

1. Объяснил, как понял задачу.
2. Проанализировал текущий контекст.
3. Предложил архитектуру.
4. Обосновал выбор стека.
5. Разделил алгоритм, backend и frontend.
6. Выделил MVP.
7. Указал риски.
8. Указал первый шаг.
9. Не начал писать код без запроса.

## Для backend MVP

Готово, если:

1. Есть регистрация.
2. Есть login.
3. Пароли хешируются.
4. Есть проверка текущего пользователя.
5. Excel-источник принадлежит пользователю.
6. Пользователь не видит чужие источники.
7. Upload валидируется.
8. Анализ можно запустить.
9. Результат анализа сохраняется.
10. Есть тестовый сценарий проверки.

## Для processing module

Готово, если:

1. Модуль независим от backend и frontend.
2. Может быть вызван отдельно.
3. Делает data audit.
4. Возвращает структурированный результат.
5. Возвращает warnings при проблемах.
6. Не строит фейковую HMM при нехватке данных.
7. Подготавливает данные для графиков.
8. Имеет понятные входы и выходы.

## Для frontend MVP

Готово, если:

1. Есть login/register.
2. Есть dashboard.
3. Есть левая панель источников.
4. Можно загрузить источник.
5. Можно выбрать источник.
6. Центральная область показывает результат анализа.
7. Есть отображение warnings.
8. Есть хотя бы базовые графики/таблицы.
