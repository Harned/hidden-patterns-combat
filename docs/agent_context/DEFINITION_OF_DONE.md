# DEFINITION_OF_DONE

## Общие критерии

Результат считается готовым только если:

1. Он соответствует предметной постановке.
2. Он проверяем.
3. Он воспроизводим.
4. Он не имитирует научный вывод без оснований.
5. Он не ломает существующую работоспособность.
6. Есть понятные команды запуска.
7. Есть описание ограничений.

## Для архитектурной итерации

Готово, если агент:

1. Объяснил, как понял задачу.
2. Проанализировал текущий контекст.
3. Предложил архитектуру.
4. Обосновал выбор стека.
5. Разделил алгоритм, backend и frontend.
6. Выделил MVP.
7. Указал риски.
8. Указал первый шаг.
9. Не начал писать код без запроса.

## Для backend MVP

Готово, если:

1. Есть регистрация.
2. Есть login.
3. Пароли хешируются.
4. Есть проверка текущего пользователя.
5. Excel-источник принадлежит пользователю.
6. Пользователь не видит чужие источники.
7. Upload валидируется.
8. Анализ можно запустить.
9. Результат анализа сохраняется.
10. Есть тестовый сценарий проверки.

## Для processing module

Готово, если:

1. Модуль независим от backend и frontend.
2. Может быть вызван отдельно.
3. Делает data audit.
4. Возвращает структурированный результат.
5. Возвращает warnings при проблемах.
6. Не строит фейковую HMM при нехватке данных.
7. Подготавливает данные для графиков.
8. Имеет понятные входы и выходы.

## Для frontend MVP

Готово, если:

1. Есть login/register.
2. Есть dashboard.
3. Есть левая панель источников.
4. Можно загрузить источник.
5. Можно выбрать источник.
6. Центральная область показывает результат анализа.
7. Есть отображение warnings.
8. Есть хотя бы базовые графики/таблицы.

## Для индивидуальных и агрегатных Marков-моделей (TASK_SPEC_011/012/013)

Готово, если:

1. Команда `make individual-models` за один прогон полностью
   воспроизводит результат на `docs/Оценка СД содержание.xlsx`.
2. Сгенерировано приблизительно **30 индивидуальных + 10 агрегатных
   HTML-отчётов** (по числу финалистов и весовых категорий).
3. Покрытие тестами: **≥ 5 pytest-тестов** для модулей `markov_individual`,
   `markov_aggregate`, `compare`, `episode_metrics`. Тесты не зависят от
   приватных Excel.
4. Для каждой матрицы переходов `A` инвариант: **сумма по любой строке
   = 1 ± 1e-6** (явный test).
5. README обновлён: цель, источник, команды запуска, ограничения,
   расположение HTML-отчётов.
6. **В коде нет русских строк, описывающих логику состояний.** Имена
   состояний в коде только из набора
   `{manoeuvring, grip, off_balance, technical_action, pause}`. Русские
   подписи — только в YAML-конфиге маппинга и в шаблонах HTML/UI.
7. Защита `>2 → log&skip` зафиксирована в audit.warnings и покрыта тестом.
8. Никаких HMM-полей в результате основного режима (HMM — Уровень 2,
   `TASK_SPEC_004/005`).
