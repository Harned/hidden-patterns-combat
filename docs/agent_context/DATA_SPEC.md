# DATA_SPEC

## Источники данных

Основной формат источников данных — Excel-файлы:

- .xlsx
- .xls

Файлы содержат данные по эпизодам соревновательной деятельности спортсменов-единоборцев.

## Опорный источник магистерской работы

- Файл: `docs/Оценка СД содержание.xlsx`.
- Лист: `Общее`.
- Турнир: Чемпионат России по самбо 2025.
- Состав: 10 весовых категорий × места 1–3 → ~30 спортсменов.
- Шапка: 3 уровня (главные категории / подгруппы / коды).
  Существующий пайплайн предобработки склеивает шапку в одно
  flatten-имя столбца. **Переиспользовать**, не переписывать.
- Эпизод записан **двумя строками** — по одной на участника поединка.
  Связка по `№ эпизода` + `Время эпизода, с.` + `Время паузы, с.`.
- Маркер конца поединка: пустое `Время паузы` у последнего эпизода
  поединка + одна-две полностью пустых строки между поединками.
- Базовые столбцы: `ФИО борца`, `№ эпизода`, `Время эпизода, с.`,
  `Время паузы, с.`, `Баллы`.

## Кодировка значений признаковых столбцов

- `1` — действие выполнено;
- `2` — действие выполнено дважды в эпизоде;
- пусто или `0` — действия нет.

**Защита от грязи.** Значения `> 2` (например, `8` в `Баллы` при
пустом признаковом блоке) — **логировать и игнорировать**. Пайплайн
не должен падать. Логирование — через стандартный warning-канал
(`code = data.value_out_of_range`, в `audit.warnings`).

## Группы признаковых столбцов (для 5-state алфавита Уровня 1)

1. **Стойка и маневрирование** — ПС × 12 направлений, ЛС × 12 направлений
   (движение без контакта).
2. **Контакты физического взаимодействия** —
   - Захваты: `О, ОО, ОР, ОсР, ОсО, Р, РР, ПО, ПР, ПсО, ПсР, СО, СР, СсО, СсР`;
   - Хваты: `ХвШ, ХвР, ХвН`;
   - Обхваты: `ОбР, ОбН, ОбТ`;
   - Прихваты: `ПрШ, ПрР, ПрН, ПрТ`;
   - Упоры: `УпГ, УпР, УпН, УпТ`.
3. **Выведение из устойчивого положения** — `ВУП-Р, ВУП-Т, ВУП-С, ВУП-О, ВУП-З`.
4. **Завершающие приёмы** —
   - Броски: `Руками, Ногами, Туловищем`;
   - `Удержание`;
   - Болевой: `На руку, На ногу`.

Маппинг «группа → список столбцов» хранится во **внешнем YAML-конфиге**
`config/state_groups.yaml`, а не в коде. См. `DOMAIN_SPEC.md`,
раздел «Уровни моделирования», и `TASK_SPEC_011_INDIVIDUAL_MARKOV.md`.

## Ожидаемые группы данных

В Excel могут быть представлены группы колонок:

1. Маневрирование / стойки
2. КФВ
3. ВУП
4. ЗАП
5. Время эпизода
6. Весовая категория
7. Спортсмен
8. Схватка
9. Эпизод

## Группы скрытых состояний

### Маневрирование

Ожидается до 24 значений:

- правосторонняя стойка;
- левосторонняя стойка;
- внутри каждой группы возможны бинарные признаки.

### КФВ

Ожидается до 29 значений, разбитых на группы:

- захваты;
- хваты;
- обхваты;
- прихваты;
- упоры.

### ВУП

Ожидается до 5 значений.

## Наблюдаемые ЗАП

Ожидаемые наблюдаемые оценки:

- ЗАП-Р
- ЗАП-Н
- ЗАП-Т
- удержание
- болевой прием на руку
- болевой прием на ногу

## Правило обработки неизвестной структуры

Если названия колонок не позволяют надежно определить группы S1/S2/S3/ЗАП/time:

1. Выполнить аудит.
2. Показать detected_columns.
3. Вернуть warnings.
4. Не строить полноценную HMM.
5. Предложить ручное сопоставление колонок или config column_mapping.

## Требования к data audit

Data audit должен включать:

- имя файла;
- список листов;
- количество строк и колонок;
- названия колонок;
- типы данных;
- количество пропусков;
- долю пропусков;
- первые строки preview;
- найденные потенциальные ЗАП-колонки;
- найденные потенциальные колонки времени;
- найденные потенциальные группы скрытых состояний;
- предупреждения.

## Важное ограничение

Нельзя молча предполагать, что Excel имеет нужную структуру.

Любое предположение о колонках должно быть явно зафиксировано в warnings или config.
