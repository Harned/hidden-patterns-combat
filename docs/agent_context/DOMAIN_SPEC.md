# DOMAIN_SPEC

## Предметная постановка

Соревновательная деятельность спортсменов-единоборцев рассматривается как скрытый процесс.

Наблюдаемая часть модели — судейские оценки ЗАП.

Скрытая часть модели — элементы соревновательной деятельности, которые могли привести к этим оценкам.

## Наблюдения

Наблюдаемыми событиями являются ЗАП:

- ЗАП-Р
- ЗАП-Н
- ЗАП-Т
- удержание
- болевой прием на руку
- болевой прием на ногу

Важно: наблюдениями являются именно ЗАП, а не действия спортсмена.

Примечание о числовой колонке «Баллы»: общая судейская оценка эпизода
(числовая колонка с малым алфавитом, например 1/2/4/6/8) считается
фактом ZAP-наблюдения. Алгоритм использует её как один канал ЗАП
(значение > 0 → ЗАП зафиксирован) и не интерпретирует конкретные
числа как разные классы ЗАП-Р/Н/Т без отдельного доменного решения.

## Скрытые состояния

Базовая скрытая структура:

- S1: стойки и маневрирование
- S2: КФВ
- S3: ВУП

Детализированная скрытая структура:

- маневры
- захваты
- хваты
- обхваты
- прихваты
- упоры
- ВУП

## Причинная цепочка

Основная логика:

маневрирование → КФВ → ВУП → ЗАП

Где:

- маневрирование — подготовительная двигательная активность;
- КФВ — контактно-физическое взаимодействие;
- ВУП — выведение из устойчивого положения;
- ЗАП — наблюдаемый судейский результат.

## Главная исследовательская задача

Построить алгоритм, который по наблюдаемым ЗАП и данным эпизодов помогает диагностировать наиболее вероятную скрытую причинную траекторию.

Алгоритм должен помогать ответить:

1. Какая скрытая траектория наиболее вероятна?
2. Какая первичная причина привела к ЗАП?
3. Какая вторичная причина усилила или завершила результат?
4. Насколько уверена модель?
5. Какие альтернативные гипотезы близки?
6. Какие методические выводы можно сделать?

## Важное методологическое ограничение

Нельзя считать задачу решенной только потому, что HMM технически обучилась.

Задача решена только тогда, когда:

1. observations действительно являются ЗАП;
2. hidden states действительно соответствуют соревновательной деятельности;
3. траектория интерпретируется как причина формирования ЗАП;
4. результат можно проверить на реальных Excel-данных;
5. вывод полезен для методической интерпретации.

## Уровни моделирования (после встречи 02.05.2026)

Алгоритм рассматривает два уровня описания соревновательной деятельности.
Они **сосуществуют**, не отменяя друг друга, но в текущем приоритете
основной — Уровень 1.

### Уровень 1. Наблюдаемая марковская цепь по эпизодам (5-state)

Состояние эпизода — одно из пяти, выводится напрямую из активности
по группам признаковых столбцов:

- `manoeuvring` — активность только в группе «стойка/маневрирование» (ПС/ЛС × 12 направлений);
- `grip` — активность в группе «контакты физического взаимодействия» (захваты, хваты, обхваты, прихваты, упоры);
- `off_balance` — активность в группе «выведение из устойчивого положения» (ВУП-Р/Т/С/О/З);
- `technical_action` — активность в группе «завершающие приёмы» (броски, удержание, болевой);
- `pause` — все группы пусты или строка-разделитель.

**Режим `single` (по умолчанию).** На эпизод выбирается один индикатор по
приоритету `technical_action > off_balance > grip > manoeuvring > pause`.
Эпизод, закончившийся броском, маркируется броском, даже если внутри был захват.

**Режим `multi` (опционально, по флагу).** Эпизод раскрывается в
последовательность непустых групп в порядке
`manoeuvring → grip → off_balance → technical_action`.

Маппинг «группа → список столбцов» — внешний YAML-конфиг
(`config/state_groups.yaml`). Никаких русских строк
непосредственно в логике состояний — только в маппинг-конфиге.

### Уровень 2. Скрытые состояния (HMM, отложено)

Историческая постановка из `TASK_SPEC_004/005`: hidden states
`маневрирование → КФВ → ВУП → ЗАП`, observations = ЗАП. Этот уровень
методологически согласован с предметной цепочкой, но требует объёма
данных, которого на текущей выборке (ЧР-2025, ~30 финалистов) может
не хватить (см. guard'ы `MIN_EPISODES`, `MIN_ZAP_EVENTS`).

Статус Уровня 2: **под пересмотром**, активация — после выполнения
основной поставки магистерской по Уровню 1
(см. `TASK_SPEC_004_HMM.md` / `TASK_SPEC_005_DETAILED_HMM.md`).

### Соответствие 5-state алфавита Уровня 1 канонической цепочке

| Каноническая цепочка | 5-state Уровня 1 | Примечание |
|---|---|---|
| маневрирование | `manoeuvring` | без вложенных направлений |
| КФВ | `grip` | без вложенной детализации (захваты/хваты/обхваты/прихваты/упоры) |
| ВУП | `off_balance` | прямое соответствие |
| ЗАП | `technical_action` | завершающие приёмы; эмпирически совпадает с фактом ЗАП |
| (нет аналога) | `pause` | явное состояние «нет активности» |

Инвариант `observations = ЗАП` сохраняется на Уровне 2; на Уровне 1
наблюдается эпизодное состояние, и ЗАП-факт встроен в `technical_action`.
