# ALGORITHM_SPEC

## Назначение алгоритма

Алгоритм должен обрабатывать Excel-источники с данными соревновательной деятельности и формировать интерпретируемый результат для пользователя.

## Главный принцип

Алгоритм должен быть независимым от сайта.

Он должен принимать источник данных и конфигурацию, а возвращать структурированный результат анализа.

## Ожидаемый общий интерфейс

Примерный интерфейс:

analyze_source(source_path, config=None) -> AnalysisResult

Название функции может быть другим, если архитектурно это обосновано.

## AnalysisResult должен включать

- source_metadata;
- data_audit;
- detected_columns;
- encoding_summary;
- basic_statistics;
- model_results;
- diagnostics;
- charts;
- warnings;
- errors;
- report.

## Минимальный baseline

Если полноценная HMM невозможна, алгоритм должен вернуть baseline:

- аудит Excel;
- preview данных;
- найденные потенциальные колонки;
- базовые распределения;
- простые графики;
- warnings;
- статус вроде baseline_only или needs_column_mapping.

## HMM / диагностический режим

Когда структура данных позволяет, алгоритм может строить HMM или другой диагностический метод.

Ожидаемые элементы HMM:

- скрытые состояния;
- наблюдения ЗАП;
- матрица переходов A;
- матрица эмиссии B;
- начальное распределение π;
- Viterbi path;
- gamma profile;
- state distribution;
- zap distribution;
- confidence / uncertainty;
- интерпретируемый отчет.

## Скрытые состояния

Минимально предметно корректная детальная структура:

- маневры
- захваты
- хваты
- обхваты
- прихваты
- упоры
- ВУП

## Наблюдения

Наблюдения — ЗАП.

Не использовать действия спортсмена как observations, если задача состоит в восстановлении причин по ЗАП.

## Графики

Алгоритм должен готовить данные для графиков в формате, удобном для frontend.

Желательные графики:

- распределение ЗАП;
- распределение скрытых состояний;
- диагностическая траектория;
- gamma heatmap;
- transition matrix heatmap;
- duration statistics;
- missing values chart.

## Требования к честности результата

Если модель не может быть построена:

- не возвращать фиктивный Viterbi path;
- не возвращать случайные скрытые состояния;
- не писать, что диагностика выполнена;
- вернуть понятные warnings.
