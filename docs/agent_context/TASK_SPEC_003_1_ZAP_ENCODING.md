# TASK_SPEC_003_1_ZAP_ENCODING

## Текущая задача

Научить processing module корректно работать с **реальной кодировкой
ЗАП** в Excel-источниках и показывать осмысленные events по каналам, а не
гистограммы `0/1`.

## Контекст

По `DOMAIN_SPEC.md` наблюдения — это ЗАП:

* ЗАП-Р, ЗАП-Н, ЗАП-Т;
* удержание;
* болевой приём на руку;
* болевой приём на ногу.

В реальном файле `docs/Оценка СД содержание.xlsx` эти метки не лежат в
одной категориальной колонке. Вместо этого они представлены набором
**отдельных колонок-каналов**, каждая из которых содержит целочисленный
счётчик «сколько раз событие произошло в этом эпизоде» (чаще всего
``0`` или ``1``, изредка ``2+``). Это **binary / count**-кодировка.

До `TASK_SPEC_003_1` baseline на такие колонки возвращал
``zap_value_counts = {"0.0": …, "1.0": …}`` — формально корректно,
но неинформативно: пользователь видит гистограмму 0/1, а не
распределение событий по каналам.

## Что должно появиться

1. **algo** классифицирует каждую ЗАП-колонку как
   ``categorical`` / ``binary`` / ``count`` / ``empty``.
2. Для ``binary`` / ``count`` baseline считает:
   * ``events`` — число эпизодов, где значение ``> 0``;
   * ``total_triggers`` — сумма значений (может быть ``> events``).
3. Все не-``empty`` ЗАП-колонки попадают в новое поле
   ``zap_events_by_channel: dict[channel_label, int]``,
   где ``channel_label`` — атомарный уровень flatten-имени (например
   ``Удержание``, ``На руку``, ``ЗАП-Р``).
4. Для ``categorical`` по-прежнему заполняется
   ``zap_value_counts``; для ``binary`` / ``count`` поле остаётся
   пустым, но значение отражается в ``zap_events`` и
   ``zap_events_by_channel``.
5. Chart-ready JSON получает отдельную диаграмму «ЗАП-события по
   каналам» (когда она непуста), и диаграмма для
   категориальных ЗАП остаётся.
6. Report и UI корректно различают два режима и не смешивают их.

## Что НЕ делает этот шаг

* Не добавляет HMM.
* Не переопределяет ``hidden states``.
* Не меняет пользовательский формат ``ColumnMappingConfig`` — только
  обогащает вывод baseline.

## Definition of Done

1. На synthetic fixture с **категориальной** колонкой ``ЗАП`` получаем
   ``zap_value_counts`` (как раньше) и **непустое**
   ``zap_events_by_channel`` для каждой распознанной метки.
2. На synthetic fixture с **бинарными** колонками (``Удержание`` /
   ``На руку`` / ``На ногу``) получаем непустое
   ``zap_events_by_channel`` и ``zap_column_kinds`` отмечает колонки
   как ``binary``/``count``.
3. На реальном `docs/Оценка СД содержание.xlsx` после preflight +
   analyze видно ненулевые события по реальным каналам (удержание,
   болевой приём, ЗАП).
4. Тесты algo и backend зелёные, ruff и tsc clean.
5. Инварианты сохранены: observations = ЗАП, HMM-полей нет.
